# 权限管理：菜单「显示/隐藏」与「父级选择」 —— Spec

Status: ready-for-agent

## Problem Statement

权限管理页目前无法完成两件日常运维必做的事：

1. **隐藏菜单**。「个人中心」这类页面要常驻导航之外（从右上角头像等入口跳转），但不应出现在侧边栏。现状 `permission` 表只有 `status`（1 启用 / 0 禁用），禁用会同时把侧边栏和路由一起拿掉 —— 想"不显示但仍可访问"没有开关可用。
2. **调整菜单层级**。「系统设置」目录要挪到「系统管理」目录之下。现状前端表单没有父级选择控件，`parent_id` 只能靠表格行上的「新增子节点」按钮隐式赋值，无法把已有节点改挂到别的父级下；后端 `update` 虽能改 `parent_id`，但没有任何存在性 / 防环 / 类型一致性校验，可把菜单挂到自己的子孙下形成死循环。

一句话：系统负责人需要一个能「运行时」调整菜单**是否在侧边栏显示**与**挂在哪个父级下**的权限管理页。

## Solution

在现有权限点模型上做两个正交的能力（见 ADR-0003）：

- **新增 `visible` 字段**（1 显示 / 0 隐藏），与 `status`（启用/禁用）两个独立维度。隐藏菜单仍保留在登录菜单树中（路由注册、权限码有效、可分配角色），仅前端侧边栏渲染时裁剪；管理端树照常返回隐藏菜单并打「已隐藏」标记。
- **表单新增「父级」选择器**：菜单类型可选任意菜单或顶层（排除自身与子孙）；按钮类型是受限的「绑定菜单」下拉（只列菜单，可换绑）；接口类型固定顶层。后端 `add` / `update` 增加 parentId 存在性、防环、类型一致性校验。

侧边栏裁剪发生在**前端渲染时**（见 ADR-0003），路由守卫不变 —— 隐藏菜单仍可 URL 直达。

## User Stories

**显示 / 隐藏**

1. 作为系统负责人，我可以把某个菜单设为隐藏（`visible=0`），以便它不出现在侧边栏但用户仍可通过 URL 访问（如「个人中心」）。
2. 作为系统负责人，我可以把某个已隐藏的菜单改回显示，以便恢复它在侧边栏的入口。
3. 作为系统负责人，我隐藏一个目录菜单时，它下面的整棵子树一并隐藏，以便"隐藏目录"的语义是隐藏整个区块。
4. 作为系统负责人，我隐藏菜单不会撤销其权限码 —— 该菜单仍可分配给角色、角色下仍可访问，以便隐藏 ≠ 禁用。
5. 作为系统负责人，我可以同时独立地「隐藏」与「禁用」同一个菜单，以便两个维度互不干扰。
6. 作为被授权的管理员，侧边栏里我看不到被我分配了但被隐藏的菜单，但我直接输入其 URL 仍能访问，以便导航简洁且不破坏已授权入口。
7. 作为系统负责人，我在权限管理页能看到所有隐藏菜单（带「已隐藏」标记），以便随时找到并改回显示。
8. 作为系统负责人，新增菜单时默认是显示状态，以便默认行为与现状一致。
9. 作为系统负责人，「显示/隐藏」开关只在类型为「菜单」时出现，以便表单不会对按钮/接口展示无意义控件。
10. 作为系统负责人，角色分配树中隐藏菜单照常出现、可分配，以便隐藏不影响授权配置。

**父级选择与层级调整**

11. 作为系统负责人，我可以把「系统设置」这类目录移动到「系统管理」目录下，以便调整导航层级。
12. 作为系统负责人，我可以把菜单移动到顶层（根），以便把菜单从目录中提升出来。
13. 作为系统负责人，父级选择器会排除我自己和我的全部子孙节点，以便我无法在界面上选择会形成环的父级。
14. 作为系统负责人，后端会拒绝非法的父级变更（父级不存在、父级是自己、父级是自己的子孙），以便绕过前端直连接口也无法造成环。
15. 作为系统负责人，我只能把菜单挂到菜单或顶层，以便层级结构类型干净。
16. 作为系统负责人，按钮的父级只能是它绑定的菜单，不能挂到按钮或接口下，以便按钮归属清晰。
17. 作为系统负责人，我可以在编辑按钮时把它换绑到另一个菜单，以便无需删除重建。
18. 作为系统负责人，接口权限点固定为顶层，表单不显示父级选择，以便接口不被嵌套进层级。
19. 作为系统负责人，移动目录时其整棵子树随之移动，以便结构保持一致。

**回显与一致性**

20. 作为系统负责人，编辑权限点时表单能正确回显 `visible`、`status`、`remark`（修复现状把 `status` 硬编码为 1、`remark` 硬编码清空的缺陷），以便配置所见即所得。
21. 作为系统负责人，MySQL 与 PostgreSQL 两套库都新增 `visible` 列，以便双库部署行为一致。
22. 作为系统负责人，历史数据迁移后 `visible` 默认为 1，以便老菜单不会被误隐藏。

## Implementation Decisions

**数据模型**

- `permission` 表新增 `visible`（1 显示 / 0 隐藏），默认 1，MySQL 与 PostgreSQL 各一条 Flyway 迁移，历史数据回填为 1。
- `visible` 仅对 `type=menu` 有意义；按钮 / 接口保持默认显示，不为其提供该控件。
- 实体、请求 DTO、树节点 VO 均透传 `visible`。新增权限点默认 `visible=1`；更新权限点可改 `visible`、`status`、`remark`。
- 现有唯一键（`permission_code`）与索引（`parent_id`、`type`）不变。

**父级规则（add / update 共用）**

- 菜单（`type=menu`）：父级只能是另一个菜单或顶层（`parent_id=0`）。
- 按钮（`type=button`）：父级只能是菜单（绑定菜单），编辑时可换绑到另一个菜单。
- 接口（`type=api`）：固定顶层，不接受父级。
- 校验：`parent_id` 指向的节点必须存在；不能是自身或自身的后代（防环）；父子类型必须符合上述规则。校验失败返回业务错误，不落库。

**管理端树**

- `GET /permission/tree` 照常返回全部启用节点（`status=1`），隐藏菜单（`visible=0`）包含其中，节点携带 `visible` 供前端标记与回显。
- 登录下发的菜单树**不变**：仍包含隐藏菜单 —— 裁剪只发生在前端侧边栏渲染时，路由守卫逻辑不动。

**前端权限管理页**

- 表单新增「父级」选择器：
  - 类型=菜单：展示所有菜单节点的下拉树 + 「顶层」选项，**排除自身与子孙**。
  - 类型=按钮：受限的「绑定菜单」下拉（只列 `type=menu` 节点），编辑可换绑。
  - 类型=接口：不显示父级控件，固定顶层。
- 表单新增「显示/隐藏」开关（仅类型=菜单时出现）；编辑回显 `visible`，并修复现状 `status` / `remark` 被硬编码的问题。
- 管理树中隐藏菜单带「已隐藏」标记。

**前端侧边栏**

- 渲染时过滤：遇到 `visible=0` 节点，连同其整棵子树一起跳过（同时满足隐藏目录 → 隐藏子树、隐藏叶子 → 隐藏自身）。
- 路由注册与守卫不感知 `visible` —— 隐藏菜单仍在树中，路由照常注册，URL 可直达。

## Testing Decisions

**好的测试是什么**：只测外部行为 —— 给定入参与登录身份，断言返回结果或抛出的业务错误；不测实现细节（不测 SQL、不测表结构、不测前端渲染）。校验拒绝路径与放行路径同等重要。

**测试接缝（两个纯单元测试 seam，扩展现有先例，无 Spring 容器）**：

1. **权限点维护 seam**（扩展 `PermissionServiceImplTest`）：`add` / `update` 的父级规则 —— 父级不存在 → 拒绝；父级为自身或后代 → 拒绝（防环）；菜单挂按钮/接口、按钮挂按钮/接口、接口挂父级 → 拒绝；合法父级（菜单挂菜单/顶层、按钮挂菜单、接口顶层）→ 放行。
2. **权限树查询 seam**（扩展 `PermissionTreeServiceTest`）：管理端树包含隐藏菜单且 `visible` 透传到节点；登录菜单树构建不受 `visible` 影响（隐藏节点仍在树中）。

**先例**：`PermissionServiceImplTest`、`PermissionTreeServiceTest`（无 Spring 容器 + Mockito 的纯单元测试）。

**不做**：前端自动化测试（前端无测试设施，沿用既有决策不引入测试框架）；侧边栏裁剪靠人工验收（隐藏后侧边栏不显示、URL 仍可直达）。

## Out of Scope

- **前端自动化测试框架**的引入。
- 菜单**拖拽排序**（排序仍走 `sort_order` 手动编辑）。
- 修改「禁用」（`status`）的既有语义 —— 禁用仍同时移除侧边栏与路由。
- 隐藏菜单的**专用入口页**（如"全部菜单"抽屉）—— 隐藏菜单靠 URL 直达或重新显示。
- 权限变更的独立审计追踪。
- 行级数据权限、多租户等更复杂的 RBAC 扩展（沿用 `CONTEXT.md` 既有边界）。

## Further Notes

- 双库（MySQL + PostgreSQL）Flyway 迁移必须同步，两套 schema 保持一致；历史数据 `visible` 回填 1。
- 领域术语以 `CONTEXT.md` 为准：权限点、菜单权限/按钮权限/接口权限、权限码、隐藏菜单、菜单父级规则。
- 本 spec 是现有 `.scratch/rbac/`（RBAC 权限控制）在权限管理页上的增量，跨引用其 issue 06（权限管理页基础 CRUD）。
- 侧边栏裁剪是"前端渲染时裁剪"而非"后端裁剪树"，这是有意为之 —— 详见 ADR-0003。
