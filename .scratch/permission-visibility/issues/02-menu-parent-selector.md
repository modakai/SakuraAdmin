# 02 — 菜单父级选择（调整层级）

**What to build:** 系统负责人可以调整菜单的层级归属：编辑某个菜单时，通过父级下拉树把它挂到另一个菜单下或提升到顶层（如把「系统设置」目录移到「系统管理」目录下）；父级下拉树排除「自身及自身全部子孙」，从根源上选不成环；后端同时对父级变更做存在性与防环校验，绕过前端直连接口也无法破坏树结构。

**Blocked by:** 01 — 菜单「显示/隐藏」全链路

**Status:** ready-for-agent

- [ ] 编辑菜单时可通过父级下拉树把该菜单移动到另一个菜单下，或选择「顶层」提升为根级节点
- [ ] 父级下拉树排除「自身及自身全部子孙」，界面上选不出会形成环的父级
- [ ] 后端对新增/更新校验父级存在性（指向的权限点存在且未删除），失败返回业务错误、不落库
- [ ] 后端防环校验：新父级不能是自身或自身后代，绕过前端直连接口也被拒绝
- [ ] 移动目录时其整棵子树随之移动，结构保持一致
- [ ] 单测覆盖（维护 seam）：父级不存在 / 挂自身 / 挂后代 → 拒绝；合法移动（挂另一菜单、挂顶层）→ 放行

**Tests:** 纯单元测试扩展权限点维护 seam —— 参数化覆盖拒绝路径（不存在 / 自身 / 后代）与放行路径（挂另一菜单 / 顶层）。
