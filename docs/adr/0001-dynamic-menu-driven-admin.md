# 管理后台采用后端动态菜单/路由驱动权限

管理后台前端曾以 `navigationRegistry`（`naive-vue-app/src/app/router/navigation.ts`）为后台页面与侧边栏菜单的**唯一事实来源**，路由静态生成、无权限概念。引入 RBAC 后，改为**后端下发菜单树**：菜单权限点（`type=menu`）存于 `permission` 表，登录接口返回当前用户可见的菜单树，前端动态 `addRoute` 并渲染侧边栏。前端不再硬编码后台导航，仅保留「组件标识 → `import()`」的映射表。

**理由**：菜单增删改可在权限管理页运行时维护，无需改前端发版；权限点表直接成为"角色登录后能看到什么"的唯一事实来源。

**被否决的替代方案**：静态注册 + 权限过滤（保留 `navigationRegistry` 为事实来源，仅按权限过滤显示）。其优点（类型安全、改动小）被「菜单无法运行时维护」的缺点压过 —— 若菜单要改只能改代码发版。代价是本决策推翻了先前 `adfe5a2` 刚统一的静态单一数据源。

**后果**：前端路由类型安全下降（路径/组件名/图标以字符串入库）；需要维护组件映射表；`navigationRegistry` 降级为「组件注册表」而非导航定义。
