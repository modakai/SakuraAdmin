# 权限点「可见性（visible）」与「状态（status）」分离，隐藏菜单保留在树中由前端裁剪

权限管理页需要两类不同的需求：菜单不进侧边栏但仍可 URL 直达（如「个人中心」），以及菜单彻底下线（如功能停用）。现状 `permission` 表仅有 `status`（1 启用 / 0 禁用），禁用会同时移除侧边栏与路由 —— 两种需求无法区分。决定新增独立字段 `visible`（1 显示 / 0 隐藏），与 `status` 正交：隐藏菜单（`visible=0`）仍保留在登录菜单树中（路由照常注册、权限码有效、可分配给角色），由前端侧边栏渲染时裁剪该节点及其整棵子树；管理端权限树照常返回隐藏菜单，以便随时改回显示。

**理由**：若改为在后端裁剪隐藏菜单，路由将不再注册，隐藏退化为禁用 —— 无法满足「不显示但可访问」的诉求。保留在树中、前端渲染裁剪，使「隐藏」与「禁用」成为两个独立语义（见 `CONTEXT.md`「隐藏菜单」）。

**被否决的替代方案**：① 复用 `status` 作为隐藏开关（单开关）—— 语义混淆，隐藏会连带撤销路由访问权；② 后端从登录树裁剪隐藏菜单 —— 破坏路由可达性，且目录隐藏的子树语义难以在后端精确表达。

**后果**：前端侧边栏渲染需过滤 `visible=0` 子树（隐藏目录时整棵子树一并隐藏）；登录菜单树结构保持不变（含隐藏节点），任何消费菜单树的组件需意识到隐藏节点仍存在；管理端树携带 `visible` 供「已隐藏」标记与回显；双库迁移需同步新增该列。
